§1 Cada operação lembra de onde veio

Toda operação (a + b, c * a, ...) cria um tensor de saída que guarda dois pedaços de memória: previous (os tensores de entrada) e _backward (uma closure que sabe propagar o gradiente pra essas entradas). Ligando essas referências, formam um DAG — grafo acíclico dirigido: nós são tensores, arestas apontam de uma operação pros seus inputs.

FIG. 1c = a + b, d = c * a. Repare que a aparece duas vezes como entrada de d — uma vez direto (aresta destacada), outra vez através de c. É esse "múltiplos caminhos" que faz o gradiente de a precisar somar duas contribuições no backward (§3).

§2 Por que a ordem de visita importa

backward() só pode processar um nó depois que todo gradiente que ele vai receber já chegou — de todo mundo que o usa como entrada. Processar fora de ordem soma gradiente parcial e propaga valores incompletos adiante. A ordem certa é a topológica reversa: a raiz primeiro, as folhas por último.

FIG. 2d alimenta dois caminhos (x e y) que só se reencontram em loss. d só pode ser processado depois que ambos, x e y, já contribuíram — mesmo d não sendo folha. A ordenação topológica (DFS que só adiciona um nó depois de visitar todos os predecessores, depois invertida) garante isso automaticamente.

§3 Backward: gradiente convergindo nos nós reusados

Rodando backward() no grafo da FIG. 1, o gradiente de a recebe uma contribuição direta de mul e uma contribuição indireta, através de c (que veio de add). As duas se somam — nunca uma sobrescreve a outra.

FIG. 3Duas setas chegam em a: uma vinda do mul direto (∂d/∂a = c), outra através do add (∂d/∂c · ∂c/∂a = a · 1). a.gradient.accumulate(...) soma as duas — é literalmente por isso que o método se chama accumulate, não set.

§4 Passando os números (o exemplo do HISTORY.md)

a = 2, b = 3. Forward: c = a+b = 5, d = c*a = 10.

PassoCálculoResultado

Verificação simbólica direta: d = (a+b)·a = a² + ab. ∂d/∂a = 2a+b = 2(2)+3 = 7 ✓, ∂d/∂b = a = 2 ✓ — bate exatamente com o grafo.
